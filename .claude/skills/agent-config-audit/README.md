# 项目全维度体检审查员

> 这是一个给 Claude Code 项目做「配置体检」的 skill。你新开一个 agent 项目时，一句话触发它，它会审查你的 slash commands、CLAUDE.md/memory、skills、subagents、MCP、hooks、plugins、checkpoints、高级设置、CLI 用法写得好不好，并给出按优先级排序的改进建议。

## 亮点

- 覆盖 Claude Code 配置的 10 个维度，评分标准提炼自各维度的最佳实践与常见坑
- 检查点分两类：`[配置]` 类对文件直接打分（✅/⚠️/❌），`[实践]` 类作使用习惯自查建议，不伪装成客观评分
- 只审「生效配置」——教学示例文件、缺失的构件都不扣分，不制造假问题
- 每条建议都指回对应模块名（如「参考 03-skills 一节」），边审边复习
- 只输出报告与建议，**不会自动改你的文件**

## 什么时候用

| 你可以这样说 | 它会做什么 |
|---|---|
| "帮我审查一下我的 agent 配置" | 扫描 `.claude/` 各构件，逐块体检 |
| "check my claude code setup" | 输出配置评分表 + 实践自查清单 |
| "audit my .claude" | 找出最该先改的几件事并指回对应模块 |
| "agent config audit" | 给项目一个总体健康评级 |

## 使用方式

```text
/agent-config-audit
```

## 它会输出什么

1. **扫描到的构件** — 列出发现的生效配置，标注哪些「未使用」、哪些是「教学示例（不计分）」
2. **配置类评分** — 每个已评估模块一张小结表（检查点 + ✅/⚠️/❌ + 说明）
3. **实践自查清单** — 无法静态判定的使用习惯项，供你对照（可选做一轮快速自评）
4. **总体评级** — 健康 / 良好 / 需改进，一句话点出最突出的问题或亮点
5. **Top 优先修复项** — 3-5 条按影响排序的改进项，每条附具体改法 + 指回对应模块名

## 审计出问题后，谁来修

这个 skill **只审、不改**——它保持只读，所以你可以随时放心跑，不会有副作用。修复由谁做，按问题类型分：

- **`[配置]` 问题**（能改文件的）→ 交给**当前项目的主对话**：审计结果已经在对话上下文里，你逐条确认「这条改 / 这条不改」，让主对话就地改。修复是需要判断的活，你在环里最合适。
- **`[实践]` 问题**（使用习惯，不是改文件）→ 没有「谁来改」，是你**自己内化**成习惯。

为什么不把修复塞进这个 skill、也不建修复 subagent：审计与修复是两件事（对应内置 `/code-review` 只审查、`/simplify`/`--fix` 才应用修复的分工）；配置修复通常少而需判断，为它开 subagent 属过度设计。**只有**当修复变成批量、机械、可并行（如几十个文件同一处错）时，才升级成一个独立的修复 skill 或 subagent——但审计与修复永远分开，绝不合并。

## 评分标准放在哪

所有检查点集中在 `references/checklist.md`，按 10 个模块分节、每条标 `[配置]`/`[实践]`。想调整审查口径，直接改那个文件即可。
